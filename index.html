    04 / FIELD NOTES

    Technical case studies.

    Anonymised technical notes aligned with the troubleshooting areas in my datacentre role. These describe investigation methods, not customer-specific incidents or measured outcomes.

    ETHERNET / LINK HEALTHCASE 01

    Investigating interface flaps

    Approach for correlating link-state changes, interface counters and system logs to narrow down an intermittent physical or configuration issue.

    Investigation flow
    1. Review interface state and recent events.
    2. Compare carrier-change counters over a known interval.
    3. Inspect transceiver, cable, FEC and error counters.
    4. Validate the peer port and document findings.
    ethtoolsysfsjournalctl
    INFINIBAND / FABRICCASE 02

    IB port stuck in Polling

    A structured path for investigating a server-side InfiniBand port that does not reach an active state.

    Investigation flow
    1. Check port state and physical link indicators.
    2. Validate cable and transceiver compatibility at both ends.
    3. Compare peer-port state and fabric visibility in UFM.
    4. Escalate with port GUID, node, port and evidence.
    UFMIB diagnosticsoptics
    AUTOMATION / VISIBILITYCASE 03

    Switch port inventory collection

    Concept for collecting interface, FDB and neighbour information across a defined switch list and normalising it for review.

    Investigation flow
    1. Define an approved read-only command set.
    2. Collect outputs from target devices.
    3. Parse MAC, VLAN, interface and state fields.
    4. Export results and retain collection timestamp.
    ShellPythonCSV

    All examples are generalised and omit customer identifiers, internal addresses, hostnames, MAC addresses, serial numbers and confidential topology details.
